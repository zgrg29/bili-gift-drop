# Windows EXE 构建与验证

日期：2026-10-24（Asia/Shanghai）。

需求：说明礼物堆积与消失行为，提供 Windows EXE，供用户后续上传 GitHub Release。

确认：当前圆形近似碰撞会让礼物弹跳并在底部堆积。默认从生成起计时 30 秒，最后 1 秒透明度降至 0 后删除；可设 5–120 秒。超出对象上限会直接移除最早对象，清空按钮会立即清空。这次未修改物理或消失行为。

实现：Node.js v24.22.1 Windows x64 SEA，将所有 src 文件作为资产内嵌。启动时展开到用户目录下按内容哈希区分的 app 子目录，通过文件模块加载原有服务，配置和图片缓存独立保存在 `%LOCALAPPDATA%\BiliGiftDrop`。默认自动打开控制面板，`--no-open` 用于自动验证。支持 `BILI_GIFT_DATA_DIR` 指定运行数据位置，源码默认路径不变。构建工具 postject 固定 1.0.0-alpha.6 并检查压缩包 SHA-256；先清除原 Node 签名证书目录再注入，生成未签名 EXE。ZIP 附带三语说明和 Node 及依赖许可声明。

产物：`dist/BiliGiftDrop-windows-x64.exe`、`dist/BiliGiftDrop-windows-x64.zip`、`dist/SHA256SUMS.txt`。build/dist 已被 Git 忽略，不含当前房间配置或个人缓存。未创建远程 Release。

验证：

- `node --test`：8/8 通过，包括三语键名与插值参数一致性。
- `node scripts/smoke-windows.mjs`：独立 EXE 在备用端口 19329 启动；首页、overlay、脚本及三语资源 HTTP 200；SSE 初始化、模拟送礼、清空、非法房间号及 Origin 拦截通过；依次保存三语后，重启 EXE 验证英语及 lifetime=45 保留。使用 build 下临时隔离数据，不修改用户当前配置。
- 首次回环测试被沙箱网络 EACCES 阻止；解除该测试网络限制后完整通过。
- ZIP 由 Windows tar 生成，随包生成 SHA-256；压缩包约 35 MB，EXE 约 94 MB。

边界：本机独立进程验证不等同全新 Windows 机器验收。自动测试使用 `--no-open`，浏览器自动打开未实机验收；OBS、窄屏三语视觉检查、长时压力测试仍待做。SC 仍为后续范围。

## 启动窗口闪退修复

用户反馈双击 EXE 后窗口立即消失。检查默认端口 19321，确认 PID 4624 的已有礼物服务仍在监听，SSE 返回 connected 状态，故重复启动触发 EADDRINUSE。原来错误处理直接 exit(1)，无法看清提示。

修复：端口占用时读取现有服务 SSE 初始化格式，确认是礼物服务后打开已有面板并退出新进程，不停止已有服务或连接。其他错误显示三语统一文案和错误码，交互终端等待回车；资源展开失败也保留错误窗口。浏览器启动改为 explorer.exe，避免 cmd start 的引号参数问题。增加 EXE 重复启动验证，并重新生成 EXE/ZIP。

验证结果：8 项规则测试通过；重新生成后 EXE 重复启动返回 0、输出已有面板地址，原服务仍 HTTP 200；静态资源、模拟、清空、三语保存与重启验证全部通过。测试辅助程序修复 SSE 长消息分块读取，避免目录响应较长时错误解析。自动测试未启动实际浏览器窗口。
