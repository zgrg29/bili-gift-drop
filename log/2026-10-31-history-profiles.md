# 历史头像与匿名礼物昵称补全（v0.6.10）

日期：2026-10-31（Asia/Shanghai）。范围：本场直播礼物历史中的观众头像、公开 UID 昵称补全；不使用 Cookie 或登录。

## 用户反馈与目标

- 匿名连接下，礼物昵称被 B 站遮罩成「首字***」；SC 昵称仍可能是完整的。
- 希望在历史记录中显示观众头像和完整昵称。
- 明确不需要 Cookie/登录，使用公开 UID 资料查询。

## 实现

- 新增 `src/server/profiles.mjs`：公开资料查询，返回 `{name, avatar}`。
  - 优先尝试事件头像缓存；昵称/头像从 `live_user/v1/Master/info` 和 `x/web-interface/card` 获取。
  - 成功缓存 1 小时，失败退避 30 秒；最多 8 个并发、512 条缓存、同 UID 并发合并。
  - 只访问公开资料，不读取或保存任何 Cookie/登录凭据。
- 礼物归一化保留 UID 和事件头像：旧版 `SEND_GIFT` 增加 `face`；`SEND_GIFT_V2` 解析根消息 field 3 的 `face`。
- `HistoryLedger` 增加观众 `avatar` 和 `updateViewer(uid,{user,avatar})`；快照/载入包含头像。
- 服务端在收到礼物/SC/大航海后异步查询资料：
  - 昵称为空或被遮罩（`首字***`）时用 UID 查询完整昵称和头像；
  - 昵称完整时只补头像（优先事件头像，缺失才查公开资料）；
  - 只在同一连接代次内更新历史，避免换房后旧查询串到新房间；
  - 通过新的 `history-update` SSE 事件只更新历史客户端；OBS overlay 不接收。
  - SC/大航海的已有头像查询也同步写入历史；解析到完整昵称时同时更新 SC 卡片/大航海队列显示。
- 控制台历史观众标题改为「头像 + 昵称」；头像只接受本地 `/cache/` 路径，加载失败或没有头像时显示昵称首字圆形占位。
- 三语新增 `historyAvatar`；头像布局在 390px 宽度下检查。
- 未改变：历史仍只在本次运行内保存、不写 SC 留言到磁盘；模拟事件不计入；金额显示和每日日元汇率保持。

## 验证

- `node --test --test-isolation=none`：49/49 通过。新增覆盖：
  - 公开资料查询返回昵称/头像、命中缓存、失败时保留事件头像并退避、同 UID 并发合并、无效 UID 不请求网络；
  - 历史观众昵称/头像更新与快照重载；
  - 控制台头像/首字占位渲染、`history-update` 更新；
  - 礼物 V2 头像字段解析；
  - 三语键和参数一致。
- 真实公开 UID 实测：两个公开接口返回昵称，头像下载并写入隔离临时缓存；未打印或保存用户敏感信息。
- 390px 历史头像布局静态渲染检查：圆形头像、长昵称换行、无头像首字占位均正常。截图 `docs/screenshots/history-avatar-390.png`。
- Windows v0.6.10 EXE/ZIP 已构建；`node scripts/smoke-windows.mjs` 隔离回归通过：启动/重复启动、HTTP/SSE、礼物/SC/大航海、历史快照与模拟排除、金额显示重启持久化、三语、内嵌全部源码逐字节一致、退出端口释放。
- 构建/截图期间按工具要求对写入 build/dist 和 Chrome 截图的命令单独申请了完全权限；测试使用临时隔离数据目录。

## 未验收与边界

- 真实匿名礼物事件到「UID 补全昵称/头像」的完整链路未在真实送礼房间逐条抓取验证；公开资料接口可能受隐私设置、风控或频率限制。
- 用 UID 反查平台遮罩昵称可能触及平台隐私/使用条款边界；仅建议用于主播本地感谢名单，不公开传播。
- 真实上舰/付费SC、OBS、完整三语窄屏、全部视频编码、长期高峰和全新 Windows 仍未验收。
- 历史头像截图未重新生成完整控制台页面；本轮为 390px 静态布局检查 + 自动化 DOM 测试。

本轮只做本地构建与验证，不提交、不打标签、不推送、不发布远程 Release。
