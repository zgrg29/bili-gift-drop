# 匿名礼物空 UID 的头像兜底（v0.6.13）

日期：2026-10-31（Asia/Shanghai）。范围：匿名礼物事件 UID 为空时仍显示事件头像；昵称限制说明。

## 现象

- 用户截图中礼物观众显示 `欠***`，头像仍是首字占位；SC 观众有完整昵称和头像。
- 实测两个活跃房间（6732538、6136246）的匿名礼物事件：`uid` 为空，`uname` 被平台遮罩成 `首字***`，但事件仍带 `face` 头像 URL。
- 原有 `updateViewer(uid, ...)` 只按 UID 找观众；UID 为空时即使头像已下载，也无法写回历史，所以显示首字占位。
- 由于 UID 也为空，公开 UID 资料查询没有可查询的标识，无法补全昵称。

## 实现

- `HistoryLedger` 新增按 key 更新：`updateViewerByKey(key, patch)`、`updateViewerByName(name, patch)`；`updateViewer(uid)` 继续可用。
- 服务端新增 `viewerKey(uid,user)`：有 UID 用 `uid:<id>`，否则用 `name:<平台遮罩名>`；礼物/SC/大航海的头像/昵称更新都带该 key。
- `history-update` SSE 改为发送 `key`；控制台用 `updateViewerByKey` 更新，兼容旧的 `uid` 字段。
- 空 UID 的礼物头像：`Profiles.resolve('', face)` 仍会缓存 `face`，返回头像；按名称 key 写回历史，头像正常显示。
- 空 UID 的昵称：保留平台遮罩名（如 `欠***`），不替换成“未知观众”；没有 UID 就不做公开资料查询，不伪造昵称。
- 未改变：礼物名称翻译、SC 翻译按钮、免费礼物过滤、金额显示、汇率、SC/大航海记录。

## 验证

- `node --test --test-isolation=none`：52/52 通过。
  - 新增空 UID 礼物观众按名称 key 接收头像、同 key 重复更新不再变化的回归；
  - 原有历史、免费礼物过滤、头像/UID、词典翻译、SC 翻译、电池、汇率、礼物 V2 解析继续通过。
- 实测：
  - 房间 6732538、6136246 的匿名礼物事件 `uid=""`、`uname` 被遮罩、`face` 存在；
  - room 81004 在观察窗口内没有捕获礼物事件（房间确认在播，虚拟主播区，标题“我要继续杀气改造了 影之刃零启动”），因此没有用该房间单独下结论；
  - 公开 UID=2 的昵称/头像查询此前已验证；
  - 源码服务端隔离连接 room 6732538 实际收到礼物后，历史快照得到 2 位观众：`uid` 长度均为 0、昵称均为平台遮罩、`avatar` 均为 true、总电池各 1；确认空 UID 头像兜底在真实事件链路生效，昵称仍无法补全。
- Windows v0.6.13 EXE/ZIP 已构建；`node scripts/smoke-windows.mjs` 隔离回归通过：启动/重复启动、HTTP/SSE、历史快照与模拟排除、金额显示重启持久化、三语、全部内嵌源码逐字节一致、退出端口释放。
- 构建/诊断期间按工具要求对写入 build/dist 的命令单独申请了完全权限；诊断只读，不发送礼物/弹幕。

## 未验收与边界

- 空 UID 的昵称无法通过公开 UID 查询补全；需要登录/Cookie、浏览器端辅助或其他授权数据源。当前版本没有引入 Cookie。
- 如果事件也没有 `face`，继续显示昵称首字占位。
- 真实直播礼物/SC、OBS、完整三语窄屏、全部视频编码、长期高峰和全新 Windows 仍未验收。
- 本轮只做本地构建与验证，不提交、不打标签、不推送、不发布远程 Release。
