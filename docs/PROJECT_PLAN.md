## 产品目标

面向使用 OBS 的 B 站主播，提供本地运行、浏览器设置的礼物掉落工具，不要求独立桌面外壳。主播连接直播间后，观众赠送的礼物以对应图片出现在透明 overlay 中，并根据金额产生不同的掉落效果。

首要成果是“真实送礼 → 正确图片与金额 → 掉落效果 → OBS 可见”的完整闭环。先完成礼物，再开发 Super Chat（醒目留言）。

## 范围和优先级

### P0：礼物掉落第一版

- 输入直播间号，明确显示连接、重连、断开和错误状态。
- 接收礼物事件，将不同消息格式转换为统一数据。
- 获取真实礼物图片，缓存资源，并为未知新礼物刷新资料。
- 按可配置金额档位计算图片尺寸、掉落数量与停留时间。
- 实现重力、旋转、碰撞、弹跳、底部堆积及过期清理。
- 配置全屏或局部掉落区域、物理参数、数量上限。
- 本地控制面板提供模拟送礼、一键清空、配置保存及 OBS 地址复制。
- OBS 浏览器源使用透明背景，控制面板与 overlay 保持同步。

### P1：Super Chat 与布局编辑

- 展示昵称、金额与正文，后台独立计时；按2026-10-24用户要求不在卡片上显示剩余时间。
- 优先按事件提供的有效时间显示，缺失时使用经核实的规则。
- 多条留言分别计时，限制可见条数并明确排队、溢出和过期行为。
- 提供同比例画布预览，支持拖动位置、调整尺寸、保存及恢复布局。
- 礼物与 SC 独立启用、配置，能够组合到同一 OBS overlay。

### 后续候选

- Windows 安装包、配置导入导出、效果预设（已有 start.cmd 和 Windows x64 便携 EXE；尚未做新环境启动验收）。
- 当前采用本地服务与浏览器设置，无 Electron 外壳开发计划。

第一版不扩展弹幕聊天栏、自动回复、TTS、抽奖、点歌、养宠或多平台接入。

## 全局要求：中文、日语、英语

三语支持属于第一版基础要求，后续新增功能必须同步提供三语，不能等全部功能完成后再补翻译。

- 设置中提供固定的「语言 / 言語 / Language」入口，选项为「简体中文」「日本語」「English」。
- 首次启动按系统或浏览器语言匹配支持的语言；无法匹配时默认英语。主播手动选择优先，保存后重启保持。
- 切换语言即时更新控制面板和 overlay 的软件文案，不中断直播间连接、不清空已有礼物或重置 SC 计时。
- 覆盖菜单、按钮、标签、提示、错误、连接状态、测试内容、布局编辑、空状态、用户可见日志以及后续安装和使用指引。
- 用户名、观众留言、平台提供的礼物原名等原始内容保留原文，不自动翻译；软件生成的周边文案需要三语。
- 金额、数字和时间按所选语言格式化；语言切换不改变礼物价值、币种或计时规则，不自动换汇。
- 文案集中存放在 `src/shared/i18n/`，分别维护 `zh-CN`、`ja`、`en` 资源，使用相同键名与参数。界面不得散落硬编码文案，也不得通过拼接碎片构造句子。
- 缺失翻译可临时回退英语，开发阶段应显式报告缺失键；正式交付要求三语键和插值参数齐全。
- 三语均验证换行、字体、长按钮与窄窗口，避免英文或日文被裁切。语言名称本身始终使用各自母语展示，便于切回。

M2 建立国际化结构和最小语言切换，M4 完成语言设置持久化及画面同步，M5 完成第一版三语验收；M6 的 SC 文案也必须同时交付三语。原有工期为初估，三语翻译与布局验收的额外工作需在 M1 后重新评估。

## 金额与事件规则

已追加最低触发单价设置（人民币）：按单个礼物判断，包含等于门槛的情况；连送不累计达到门槛。默认 0 不限，免费礼物仅在门槛 0 且免费开关开启时触发。低于门槛仍记录事件。当前原型已实现三语设置、保存同步及过滤。

以下是待验证的设计起点，不代表已经实现或确定默认数值：

| 输入 | 建议影响 | 边界 |
| --- | --- | --- |
| 本次总金额（单价 × 本次数量） | 单个图标尺寸线性缩放 | 用户设置最小/最大尺寸与满尺寸金额；超额封顶 |
| 本次新增赠送数量 | 掉落数量 | 每事件上限、全局存活上限、队列上限 |
| 本次总金额 | 效果档位、停留时间或额外礼物雨 | 限制时长与额外生成数量 |

- 内部金额使用整数和明确单位，验证平台字段后统一换算，避免浮点累计误差。
- 连击累计数与本次新增数分开处理；同一礼物只生成一次对应效果。
- 免费礼物单独配置是否触发，不直接套用付费金额规则。
- 盲盒的实际支付金额与爆出礼物价值分别保留；采用哪个金额触发效果需明确标注。
- 未知礼物可先展示名称或占位图并刷新图片；获取失败不能阻断其他礼物。
- 重连后不盲目回放历史送礼；SC 必须判断是否仍在有效期。

## 初步工程结构

当前实现采用无外部 npm 依赖的 Node.js ESM JavaScript、本地 HTTP/SSE 服务和 Canvas 浏览器画面。早期 TypeScript 与成熟物理引擎建议尚未实施；后续按维护性与性能验证结果评估。

```text
docs/                  规划、接入验证及使用说明
log/                   讨论纪要、决策和开发进展（纳入版本控制）
src/                   当前原型实现
  server/              直播间连接、资料缓存、本地服务
  shared/              统一事件、配置和金额单位
    i18n/              zh-CN、ja、en 文案资源与语言工具
  control/             主播控制面板与布局预览
  overlay/             OBS 透明画面及物理渲染
tests/                 当前关键规则、协议和三语测试
data/ cache/ logs/     运行时生成数据（已忽略，不提交）
```

控制面板负责配置，接入层负责解析和规范化事件，渲染层不直接解析 B 站协议。优先使用成熟物理引擎；仅在评估后决定是否采用 GiftDropper 的代码。
