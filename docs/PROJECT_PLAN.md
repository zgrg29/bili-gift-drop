# 项目规划与工程进度

更新时间：2026-10-24（Asia/Shanghai）。

## 产品目标

面向使用 OBS 的 B 站主播，提供独立的本地礼物掉落工具。主播连接直播间后，观众赠送的礼物以对应图片出现在透明 overlay 中，并根据金额产生不同的掉落效果。

首要成果是“真实送礼 → 正确图片与金额 → 掉落效果 → OBS 可见”的完整闭环。先完成礼物，再开发 Super Chat（醒目留言）。

## 范围和优先级

### P0：礼物掉落第一版

- 输入直播间号，明确显示连接、重连、断开和错误状态。
- 接收礼物事件，将不同消息格式转换为统一数据。
- 获取真实礼物图片，缓存资源，并为未知新礼物刷新资料。
- 按可配置金额档位计算图片尺寸、掉落数量与停留时间。
- 实现重力、旋转、碰撞、弹跳、底部堆积及过期清理。
- 配置全屏或局部掉落区域、物理参数、数量上限。
- 本地控制面板提供模拟送礼、一键清空、配置保存及 OBS 地址复制。
- OBS 浏览器源使用透明背景，控制面板与 overlay 保持同步。

### P1：Super Chat 与布局编辑

- 展示昵称、金额、可选正文和剩余时间。
- 优先按事件提供的有效时间显示，缺失时使用经核实的规则。
- 多条留言分别计时，限制可见条数并明确排队、溢出和过期行为。
- 提供同比例画布预览，支持拖动位置、调整尺寸、保存及恢复布局。
- 礼物与 SC 独立启用、配置，能够组合到同一 OBS overlay。

### 后续候选

- Windows 一键启动或安装包、配置导入导出、效果预设。
- 是否采用 Electron 桌面外壳，待本地网页原型验证后决定。

第一版不扩展弹幕聊天栏、自动回复、TTS、抽奖、点歌、养宠或多平台接入。

## 金额与事件规则

以下是待验证的设计起点，不代表已经实现或确定默认数值：

| 输入 | 建议影响 | 边界 |
| --- | --- | --- |
| 礼物单价 | 单个图标尺寸 | 最小和最大尺寸 |
| 本次新增赠送数量 | 掉落数量 | 每事件上限、全局存活上限、队列上限 |
| 本次总金额 | 效果档位、停留时间或额外礼物雨 | 限制时长与额外生成数量 |

- 内部金额使用整数和明确单位，验证平台字段后统一换算，避免浮点累计误差。
- 连击累计数与本次新增数分开处理；同一礼物只生成一次对应效果。
- 免费礼物单独配置是否触发，不直接套用付费金额规则。
- 盲盒的实际支付金额与爆出礼物价值分别保留；采用哪个金额触发效果需明确标注。
- 未知礼物可先展示名称或占位图并刷新图片；获取失败不能阻断其他礼物。
- 重连后不盲目回放历史送礼；SC 必须判断是否仍在有效期。

## 初步工程结构

建议从 TypeScript 本地服务与浏览器画面原型开始；具体依赖需验证后确定，当前不视为已选定。

```text
docs/                  规划、接入验证及使用说明
log/                   讨论纪要、决策和开发进展（纳入版本控制）
src/                   后续实现
  server/              直播间连接、资料缓存、本地服务
  shared/              统一事件、配置和金额单位
  control/             主播控制面板与布局预览
  overlay/             OBS 透明画面及物理渲染
tests/                 后续添加关键规则与接入回归用例
data/ cache/ logs/     运行时生成数据（已忽略，不提交）
```

控制面板负责配置，接入层负责解析和规范化事件，渲染层不直接解析 B 站协议。优先使用成熟物理引擎；仅在评估后决定是否采用 GiftDropper 的代码。

## 验证重点

- 关键规则用例：金额边界、连击增量、重复事件、免费礼物、盲盒口径、超量截断与过期清理。
- 图片验证：已知礼物、未知 ID、图片链接失败与资料刷新失败。
- 接入验证：正常连接、错误房间号、鉴权失效、网络中断及重连。
- OBS 验证：1920×1080 画布透明背景，场景切换、浏览器源刷新和不同画布尺寸。
- 压力验证：用模拟事件持续输入，观察对象数、队列、内存是否受限；性能目标在 M2 建立基线后确定。
- 真实直播验证需有实际事件证据；模拟成功不能替代真实连接验证。
